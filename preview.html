04

差在哪

同一个任务，两条路。点击任意步骤展开它要做什么。

时间长度 旧流程 · 3 天 新流程 · 半天 （同比例尺）

旧流程

5 步 · 约 3 天
1接到策划案对接沟通
口头 + 文档对接，产出一份「理解」。
2找参考、定风格页偏慢
已用 AI 辅助生图，但产出物仍是「给人看的参考」。
3补完内页最耗时
照着策划案一页页补齐。风格定完之后基本是重复执行，却占掉大头时间。
4甲方确定来回改
提交静态设计稿确认，甲方看不到最终效果，容易来回改稿。
5切图给程序交付终点
切图标注后交给程序，设计侧交付到此为止。
终点：切图包

新流程

7 步 · 约半天
1接到策划案规范化
收齐三样：规范格式的策划案、素材图包、策划 PDF。输入标准化，是 AI 接得住的前提。
2找风格参考1–2 张
标注点击框、UI 风格、页面风格。参考从「给人看」变成「能喂给 AI 的锚点」。
3写提示词AI 介入
调用 UI/UX Pro Max 转成结构化提示词，这一步决定产出质量的稳定性。
4直接生成界面AI 直出
直出可交互 HTML，一次成型，之后靠对话微调。产出物从静态稿变成能点的成品。
5给甲方定稿所见即所得
甲方看到的是能点的界面，不是效果图，改稿来回明显减少。
6制作现场程序AI 介入 · 新增
html-to-unity，把定稿 HTML 转成 Unity 界面。这一步原来是程序的活。
7推送 git 库发包 · 新增
推送到 git 仓库，即发包给现场，设计侧直达交付终点。
终点：发包完成（原属程序环节）

新流程多出来的第 6、7 步，原本是程序的活——设计侧的交付终点从「切图」后移到了「发包」，中间不再有交接。

05

整条链路只靠两个 skill

流程看着有 7 步，真正需要新学的只有两个动作，其余步骤和以前一样。

SKILL 01

UI/UX Pro Max

把「风格参考 + 策划案」转成结构化提示词，直出可交互 HTML 界面。对应第 3–4 步。

  • 输入：风格参考图、规范化的策划案、素材图包
  • 动作：写提示词 → 生成界面 → 对话微调
  • 产出：可交互 HTML 界面
SKILL 02

html-to-unity

把定稿的 HTML 界面 1:1 转成 Unity 界面，省掉切图与还原对齐。对应第 6 步。

  • 输入：定稿的可交互 HTML
  • 动作：转换 + 补全缺失组件
  • 产出：Unity 程序（可直接推送 git）

对应 STEP 03–04
3

对应 STEP 05
4

生成 Unity UI Toolkit 程序后推仓库，等于直接发包给现场，设计侧交付完成。

对应 STEP 06–07

前面两步做扎实，后面两步基本只是对话微调。
